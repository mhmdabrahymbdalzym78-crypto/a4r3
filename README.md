# إيجل سيركت — Eagle Circuit

مختبر عربي تفاعلي لبناء دوائر التيار المستمر. يتضمن محررًا حرًا للعناصر والأسلاك، ومحرك تحليل عقدي معدّل (MNA)، وأجهزة قياس، وتأثيرات ضوئية للمصابيح، وتقدير سرعة انجراف الإلكترونات. كما يتضمن تسجيل دخول اختياريًا عبر Supabase ولوحة إدارة لا يملكها إلا البريد المحدد في قاعدة البيانات.

## أي ملف أفتح؟

- **Eagle-Circuit-Offline.html**: نسخة مستقلة كاملة للمحاكاة تعمل عند فتحها مباشرة من Chrome، حتى دون خادم أو إنترنت. تحفظ الدوائر محليًا، وتدعم تصديرها واستيرادها كملفات JSON. هذه النسخة لا تحتوي على حسابات سحابية أو لوحة المشرف؛ ذلك يحتاج إعداد Supabase في نسخة المصدر.
- **index.html**: مدخل مشروع المصدر. فتحه مباشرة من مدير الملفات لا يشغّل React/Vite؛ يعرض رابط النسخة المستقلة. لتشغيل النسخة السحابية الكاملة اتبع خطوات التطوير أدناه.

## تشغيل مشروع المصدر

المتطلبات: Node.js 20 أو أحدث وnpm.

للنشر على Vercel، اتبع الخطوات في [DEPLOY-VERCEL.md](DEPLOY-VERCEL.md). يتضمن المشروع إعداد Vite والبناء وإعادة توجيه مسارات التطبيق، بينما يلزم إعداد Supabase منفصلًا لتفعيل الحسابات ولوحة المشرف.

```bash
npm install
npm run dev
```

افتح عنوان Vite المحلي الظاهر في الطرفية، غالبًا `http://localhost:5173`.

لفحص أنواع TypeScript والاختبارات وبناء ملفات النشر:

```bash
npm test
npm run build
npm run preview
```

لا تفتح `src/main.tsx` أو `index.html` مباشرة كملف محلي. ملفات TypeScript وReact يجب أن تمر عبر Vite.

## إعداد الحسابات ولوحة المشرف (Supabase)

نظام الحسابات في المصدر يستخدم واجهات Supabase Auth وPostgREST وEdge Functions. الحماية ليست إخفاء زر لوحة المشرف؛ استدعاء RPC وسياسات RLS ووظيفة الحذف تفحص هوية البريد من JWT على الخادم.

1. أنشئ مشروعًا في Supabase.
2. انسخ `.env.example` إلى `.env.local`، ثم أدخل `Project URL` و`anon/publishable key` في المتغيرين `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.
3. افتح SQL Editor في Supabase ونفّذ الملف `supabase/migrations/202611200001_eagle_initial.sql` كاملًا.
4. انشر وظيفة حذف الحسابات من مجلد المشروع باستخدام Supabase CLI:

   ```bash
   supabase login
   supabase link --project-ref YOUR_PROJECT_REF
   supabase functions deploy admin-users
   ```

5. في Authentication → URL Configuration اضبط Site URL وعناوين Redirect المناسبة لموقعك، وفعّل تأكيد البريد الإلكتروني إن أردت.
   - التسجيل يطلب الرجوع إلى جذر الموقع الحالي؛ لا يحتاج التطبيق إلى مسار `/auth/callback` منفصل. أضف نطاق الموقع المنشور وعنوان التطوير `http://localhost:5173/**` إلى Redirect URLs.
   - لتفعيل رسالة التحقق المصممة، افتح Authentication → Email Templates → Confirm signup، وضع موضوعًا مثل «فعّل حسابك في Eagle Circuit ⚡» وانسخ قالب `supabase-confirm-signup.html` كاملًا إلى HTML Body. صورة الرسالة موجودة في `public/eagle-circuit-email-hero.png`.
6. أنشئ حسابًا عاديًا من صفحة التسجيل باستخدام البريد `mhmdabrahymbdalzym78@gmail.com`، ثم أكّد البريد وسجّل الدخول به. لا توجد كلمة مرور افتراضية مضمّنة في المشروع؛ أنت تنشئها بنفسك أثناء التسجيل.
7. اختبر بحساب آخر: يجب ألا يرى لوحة المشرف، ولا يستطيع قراءة حسابات الآخرين أو حذفها.

**مهم جدًا:** لا تضع `SUPABASE_SERVICE_ROLE_KEY` أو أي سر إداري في `.env.local` أو داخل ملفات `VITE_` أو JavaScript. وظيفة `admin-users` تستخدم مفاتيح الخادم من بيئة Supabase فقط. احفظ نسخة احتياطية من قاعدة البيانات قبل حذف حسابات حقيقية.

لشرح كامل لتأكيد البريد واختباره، راجع [EMAIL-VERIFICATION-SETUP.txt](EMAIL-VERIFICATION-SETUP.txt). يجب أن تكون **Confirm email** مفعّلة في Supabase؛ قالب الرسالة وحده لا يفرض تأكيد البريد.

## ما الذي يحمي حساب المشرف؟

- عنوان المشرف ثابت داخل SQL وEdge Function: `mhmdabrahymbdalzym78@gmail.com`.
- `public.is_eagle_admin()` يتحقق من البريد الموجود في JWT الموقّع، وليس من نص يرسله المتصفح.
- RLS تسمح للمستخدم بقراءة ملفه الشخصي ودوائره فقط؛ المشرف يمكنه قراءة ملفات المستخدمين.
- حذف الحسابات يتم داخل Edge Function بعد التحقق من الجلسة والبريد، ويُرفض حذف حساب المشرف نفسه أو حساب المشرف الأساسي.
- لا يوجد إنشاء ترقية مشرف من واجهة المستخدم.

## إمكانات المحاكي

- توالٍ وتوازٍ ودوائر مركبة، مع نقاط تفرّع وأسلاك حقيقية في نموذج الحساب.
- بطارية بمقاومة داخلية، مقاومات، مصابيح، مفاتيح، أميتر وفولتميتر.
- سحب العناصر ونقاط التفرّع بالماوس أو اللمس، والتوصيل باختيار طرفين أو إنشاء نقطة تفرع على اللوحة.
- مقاومة المصباح والمقاومة العادية قابلتان للتعديل. يمكن وضع أجهزة القياس في أي موضع على اللوحة، لكن يجب توصيل الأميتر على التوالي والفولتميتر على التوازي للحصول على قياس صحيح.
- حساب الجهد والتيار والقدرة لكل عنصر وسلك، وسطوع المصابيح وفق القدرة المستهلكة.
- مقاومة السلك حسب المادة والطول ومساحة المقطع؛ تقدير سرعة انجراف الإلكترونات حسب التيار ومادة السلك ومساحة المقطع.
- حفظ محلي في المتصفح، ومكتبة دوائر سحابية للحسابات بعد إعداد Supabase.
- مكتبة تعليمية واختبارات محرك الحل في ملفات المصدر.

## افتراضات وحدود علمية

- تحليل تيار مستمر DC لشبكات مقاومات خطية ومصادر جهد ذات مقاومة داخلية، بطريقة MNA.
- النحاس: `1.68×10⁻⁸ Ω·m`، والألومنيوم: `2.82×10⁻⁸ Ω·m` عند قرابة 20°C.
- كثافة الإلكترونات تقريبية: النحاس `8.47×10²⁸ m⁻³`، والألومنيوم `1.806×10²⁹ m⁻³`.
- مقاومة الأميتر الداخلية `0.01 Ω`، والفولتميتر `10 MΩ`، والمفتاح المغلق `0.001 Ω`.
- المصابيح ممثلة بمقاومات ثابتة؛ لا يوجد نموذج فتيلة حراري. لا يدعم الإصدار الحالي AC أو المكثفات أو الملفات أو المحاكاة العابرة أو العناصر غير الخطية.
- رسوم حركة الإلكترونات توضيحية ومسرّعة؛ سرعة الانجراف الرقمية هي تقدير فيزيائي ولا تعني سرعة انتقال الإشارة الكهربائية.
- الأداة تعليمية وليست برنامج اعتماد هندسي أو بديلًا عن إجراءات السلامة وأجهزة القياس الحقيقية.

## حجم المشروع

لم أضف ملفات ضخمة بلا وظيفة للوصول إلى رقم 100 MB؛ ذلك سيبطئ التحميل ويصعّب النقل دون تحسين دقة المحاكاة. المشروع يعتمد على الشيفرة والرسومات المتجهة ويُفترض أن يبقى خفيفًا. إن أُضيفت لاحقًا مكتبة كبيرة من نماذج ثلاثية الأبعاد أو فيديوهات تعليمية محلية، فستكون حزمة اختيارية واضحة وليست حشوًا داخل النسخة الأساسية.
